# Source audit and backend discrepancies

Audit date: October 11, 2026. Sources: `feradel.render.api/server.js`, canonical routers/controllers/services, `openapi/openapi.json`, `docs/api`, `support/serialize.js`, the OpenXML compiler, and `feradel.auth.api/routes/api/v1/auth/service.js`. Frontend conventions/branding came from `feradel.sign.client/src/styles.css` and `feradel.licensee/public/branding/fera/logos/render/fera-render-light.svg`.

| Contract area                  | Verified implementation                                                                                              | Demo handling                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Inventory                      | 46 canonical operations plus 46 aliases                                                                              | 42 public operations executable; 4 HMAC infrastructure operations documentation-only                                      |
| Auth                           | `POST /api/v1/auth`, `instance` header, email/password, response `{token}`                                           | Transient JWT session, `x-auth-token` reuse; separately provisioned API-key account option                                |
| PDF document                   | Controller JSON-encodes the base64 string returned by `FeradelPdf.toPdf`                                             | Recognizes JSON-string/base64 as PDF; no invented response object                                                         |
| PDF reports                    | PDF helper calls an external renderer with transformed source as encoded XSL-FO                                      | Sample emits XSL-FO, not HTML                                                                                             |
| Forms discovery                | `form`/`pdf` encoded string or owner-scoped template lookup                                                          | Corrects generic OpenAPI render-payload example                                                                           |
| Forms rendering                | Stored `<file>` plus `<mapping>`; body `contentType` selects PDF/JSON                                                | Generates the actual wrapper and tests mapping before saving                                                              |
| Text serialization defect      | Result-tree `.toString()` XML-escapes text output (`&` → `&amp;`) inside JSON                                        | Minimal local service fix uses `destination: "serialized"`; regression covers quotes, slashes, newlines and Unicode       |
| DOCX                           | Manifest `<root><file folder/name transform>`; binary or metadata JSON/base64; `asPdf`                               | Real manifest template; genuine ZIP/XML/text inspection                                                                   |

| Literal package                | JSON `package` or `content`; four required parts, literal only, safety checks                                        | Valid literal package asset/example                                                                                       |
| JSON serialization             | `object-to-xml`, top-level `data`, repeated array elements, null empty elements                                      | Same element conventions, corrected UTF-8 declaration                                                                     |
| Dataset inference              | Path UUID not used; returns a descriptive schema tree, no persistence                                                | UUID UI input remains per canonical contract; returned tree must be saved explicitly                                      |
| Dataset validation             | Parses stored schema/sample JSON only                                                                                | Clearly limited; no claim of schema validation of supplied input                                                          |
| Dataset permissions            | Get/tree/validate lack explicit service permission calls                                                             | Matrix records actual behavior; JWT/product middleware remains unchanged                                                  |
| Mapping suggest                | Same service handler as resolve; returns matching stored records                                                     | No invented recommendation algorithm                                                                                      |
| Template compile/scan/validate | Path UUID drives lookup; generic render body is unnecessary                                                          | Corrected examples use `{}`                                                                                               |
| Assignments                    | `{assignments:[{componentUuid,placement,sortOrder,enabled,condition}]}`; PREAMBLE/POSTAMBLE only                     | Explicit replace operation; header/footer placement unavailable                                                           |
| Native components              | `EDIT.TEMPLATE.XSLT` additionally required for native source                                                         | Permission displayed; never bypassed                                                                                      |
| Direct XML                     | Uses `xsl`, returns `{result}`; imported edit permission is unused                                                   | Source-accurate request; documents missing check without changing security                                                |

The serialization change is the only backend implementation fix made. It does not change authentication, permissions, routing or tenant scope. The same fix is needed for direct text XSLT results to preserve literal characters. The patch includes the regression test and can be applied from a Render checkout with `git apply ../demo.ferarender/docs/backend-serialization.patch` after reviewing local differences. It has **not** been deployed.

External PDF renderer checkbox/choice conventions cannot be completely audited in this repository. The sample uses `true` for a checkbox and exact choice text; the UI exposes actual renderer metadata, allows literals, and checks the returned PDF field state. These conventions are not claimed as live-qualified without a configured renderer/account.

Backend full `npm test` was attempted but stopped during its legacy test runner before tests ran: **Verified RDS CA bundle is not configured**. The isolated serialization regression and source-engine mapping/report/DOCX/composite qualification pass without database access. No database/TLS/security configuration was changed to bypass this limitation.
